Pull request: Password Hashing Service (BCrypt cost 12)
Requesting closure of issue: #34

Note:
Introduces `PasswordHasher` as the single point of responsibility for password hashing and verification across the monolith. BCrypt at cost factor 12 is mandated by System Design §10.2. The cost factor is configurable via `stash.security.bcrypt-cost` so it can be bumped in a future migration without a code change. Raw passwords must never appear in logs — enforced by code comments and a negative test. No registration, login, or password-reset endpoints in this PR — those ship in later v0.2 issues and will inject `PasswordHasher` rather than calling BCrypt directly.

**Backend**

* Added `monolith/src/main/java/com/stash/platform/user/service/PasswordHasher.java`:
  * Spring `@Service` — the only class in the codebase responsible for password hashing and verification
  * Wraps Spring Security's `BCryptPasswordEncoder`
  * **`hash(plaintext)`** — returns a BCrypt hash string (`$2a$12$...`) safe to store in `user_module.users.password_hash`; throws `IllegalArgumentException` if plaintext is null or blank
  * **`verify(plaintext, storedHash)`** — constant-time comparison via `encoder.matches()`; returns `false` (not an exception) if either argument is null
  * Constructor injects `@Value("${stash.security.bcrypt-cost:12}")` — default **12** per System Design §10.2
  * Logs only the cost factor at startup (`PasswordHasher initialised with BCrypt cost factor 12`) — never the password
  * Javadoc documents security invariants: no raw passwords in logs, storage, return values, or exceptions

* Configuration:
  * `application.yml` — `stash.security.bcrypt-cost: 12` (production default)
  * `application-local.yml` — `stash.security.bcrypt-cost: 12` (local dev)
  * `application-test.yml` — `stash.security.bcrypt-cost: 4` (low cost for fast Spring integration tests; **never** for production)

* No new Maven dependencies — uses `BCryptPasswordEncoder` from the existing `spring-boot-starter-security` dependency

* No wiring into registration, login, or password-reset flows yet — consumers ship in v0.2-008+

**Tests**

* `PasswordHasherTest` — pure unit tests (no Spring context, no Docker):
  * **`hash()`**
    * Produces a non-null, non-blank string
    * Produces a valid BCrypt string starting with `$2a$`
    * Two hashes of the same password differ (random salt per call)
    * Throws `IllegalArgumentException` for null or blank password
  * **`verify()`**
    * Returns `true` for the correct password
    * Returns `false` for a wrong password
    * Returns `false` for empty, null plaintext, or null stored hash
    * Case-sensitive mismatch returns `false`
  * **Security: raw password must not appear in logs** (issue DoD negative test)
    * `hash()` — captures Logback output via `ListAppender`; asserts no log message contains the raw password
    * `verify()` — same for both correct and incorrect verification attempts; asserts neither the correct nor wrong password appears in logs
  * Tests construct `new PasswordHasher(4)` directly for speed — cost 4 is BCrypt minimum and acceptable in tests only; production always uses cost 12 via the application property

**Works / doesn't work**

* ✅ `PasswordHasher.hash()` produces valid BCrypt strings at cost 12 in production
* ✅ `PasswordHasher.verify()` correctly matches and rejects passwords
* ✅ Cost factor configurable via `stash.security.bcrypt-cost`
* ✅ Raw passwords never logged during `hash()` or `verify()` (negative test passes)
* ✅ All unit tests pass with JDK 21 — no Docker required
* ⚠️ Not yet used by registration, login, or password-reset services — those inject `PasswordHasher` in later PRs
* ⚠️ Bumping cost factor in production does not re-hash existing passwords — a separate migration job would be needed when cost is increased

**How to verify**

**Step 1 — Run the unit tests**

From the repo root:

Linux/Mac:
```bash
mvn clean test -pl monolith -Dtest=PasswordHasherTest
```
Windows (PowerShell):
```powershell
mvn clean test -pl monolith "-Dtest=PasswordHasherTest"
```

Confirm all nested test groups pass:
* `hash()` — format, uniqueness, null/blank rejection
* `verify()` — correct/wrong/null cases
* `security: raw password must not appear in logs` — both `hash_does_not_log_password` and `verify_does_not_log_password`

**Step 2 — Confirm production cost factor in config**

Open `monolith/src/main/resources/application.yml` and confirm:

```yaml

  security:
    bcrypt-cost: 12
```

Repeat for `application-local.yml` (also `12`). Confirm `application-test.yml` uses `4` for test profile only.

Windows (PowerShell):

`PasswordHasher initialised with BCrypt cost factor 12`

**Step 4 — Quick manual sanity check (optional)**

In a `jshell` or scratch test (not committed), or by temporarily adding a one-off test:

```java
var hasher = new PasswordHasher(12);
String hash = hasher.hash("TestPassword1!");
System.out.println(hash);           // starts with $2a$12$
System.out.println(hasher.verify("TestPassword1!", hash));  // true
System.out.println(hasher.verify("WrongPassword", hash));   // false
```

Confirm the printed hash starts with `$2a$12$` and verify returns the expected booleans. Do not commit passwords or scratch output.

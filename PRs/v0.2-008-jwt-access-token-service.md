Pull request: JWT Access-Token Issuer with Claims per Spec
Requesting closure of issue: #35

Note:
Introduces `JwtTokenService` as the single point of responsibility for issuing and verifying JWT access tokens per System Design §7.1. Tokens are HS256-signed, short-lived (15 minutes), and carry denormalised authorisation claims so the API layer can make decisions without a database round-trip on every request. Key rotation is supported: one active signing key issues new tokens; previous verification keys remain accepted during the rotation window. Signing key material and token strings must never appear in logs — enforced by code comments and negative tests. No login endpoint, JWT filter, or refresh-token flow in this PR — those ship in v0.2-009+ and will inject `JwtTokenService` rather than calling JJWT directly.

**Backend**

* Added `monolith/src/main/java/com/stash/platform/user/service/JwtTokenService.java`:
  * Spring `@Service` — issues and verifies JWT access tokens
  * **`issue(User user)`** — builds and signs a compact JWT using the active signing key
  * **`verify(String token)`** — parses and validates signature, expiry, and required claims; returns `AccessTokenClaims`
  * Algorithm: **HS256** via JJWT (`Jwts.SIG.HS256`)
  * Tries all verification keys in order (active signing key first, then previous rotation keys) until one succeeds

* Added `monolith/src/main/java/com/stash/platform/user/service/AccessTokenClaims.java`:
  * Record returned after successful verification: `userId`, `kycStatus`, `subscriptionTier`, `accountStatus`
  * Maps JWT claims to domain enums (`KycStatus`, `SubscriptionTier`, `AccountStatus`)

* Token claims per System Design §7.1:
  * `sub` — user UUID (string)
  * `iat` — issued-at (epoch seconds)
  * `exp` — expiry (`iat` + 15 minutes, configurable)
  * `kyc_status` — string enum value from `User.getKycStatus()`
  * `subscription_tier` — string enum value from `User.getSubscriptionTier()`
  * `account_status` — string enum value from `User.getAccountStatus()`

* Key rotation:
  * **Active signing key:** `stash.security.jwt.signing-key` (base64-encoded HS256 secret, min 32 bytes decoded)
  * **Previous verification keys:** `stash.security.jwt.verification-keys` — comma-separated base64 secrets; empty by default
  * Verifier accepts tokens signed by any key in the combined list; only the active key is used for `issue()`
  * Expired tokens fail immediately (no key retry) — expiry is definitive

* Configuration:
  * `application.yml`:
    * `stash.security.jwt.signing-key: ${JWT_SIGNING_KEY}` — production value from secret manager / env
    * `stash.security.jwt.verification-keys: ${JWT_VERIFICATION_KEYS:}` — optional rotation keys
    * `stash.security.jwt.access-token-expiry-minutes: 15`
  * `application-local.yml` — placeholder base64 signing key for local dev (never use in production)
  * `monolith/src/test/resources/application-test.yml` — test signing key for Spring integration tests

* Dependencies added to `monolith/pom.xml`:
  * `io.jsonwebtoken:jjwt-api:0.12.6`
  * `io.jsonwebtoken:jjwt-impl:0.12.6` (runtime)
  * `io.jsonwebtoken:jjwt-jackson:0.12.6` (runtime)

* Security invariants documented in Javadoc:
  * Signing key bytes never logged
  * Token strings never logged in full
  * Verification failures logged at DEBUG without token value

* Depends on `User` entity (v0.2-002) for `issue()` — no auth endpoints wired yet

**Tests**

* `JwtTokenServiceTest` — pure unit tests (no Spring context, no Docker):
  * **`issue()`**
    * Returns a non-null, non-blank JWT string
    * JWT has three dot-separated parts (header.payload.signature)
    * Issued token is immediately verifiable
  * **`verify()` — happy path**
    * Extracts correct `userId` from `sub`
    * Extracts `kyc_status`, `subscription_tier`, and `account_status` claims correctly
  * **`verify()` — failure cases** (issue DoD)
    * Throws `ExpiredJwtException` for an expired token
    * Throws `JwtException` for a bad signature
    * Throws `JwtException` for a malformed string
    * Throws `JwtException` when required claim `kyc_status` is missing
    * Throws `JwtException` when required claim `account_status` is missing
  * **Key rotation** (issue DoD)
    * Token signed by previous key is accepted during rotation window
    * Token signed by active key is accepted when rotation keys are configured
    * Token signed by an unknown key is rejected even with rotation configured
  * **Security: signing key must not appear in logs** (issue DoD negative test)
    * Signing key not logged during `issue()` or `verify()`
    * Token string not logged during issue, verify, or failed verify
  * Tests construct `JwtTokenService` directly with test base64 keys — no Spring profile required

**How to verify**

**Step 1 — Run the unit tests**

From the repo root:

Linux/Mac:
```bash
mvn clean test -pl monolith -Dtest=JwtTokenServiceTest
```
Windows (PowerShell):
```powershell
mvn clean test -pl monolith "-Dtest=JwtTokenServiceTest"
```

Confirm all nested test groups pass:
* `issue()` — format and immediate verifiability
* `verify() — happy path` — all four claims extracted
* `verify() — failure cases` — expired, bad signature, malformed, missing claims
* `key rotation` — previous key accepted, unknown key rejected
* `security: signing key must not appear in logs` — key and token never logged

**Step 2 — Confirm JWT config**

Open `monolith/src/main/resources/application.yml` and confirm:

```yaml
stash:
  security:
    jwt:
      signing-key: ${JWT_SIGNING_KEY}
      verification-keys: ${JWT_VERIFICATION_KEYS:}
      access-token-expiry-minutes: 15
```

Confirm `application-local.yml` has a placeholder signing key for local dev only.

**Step 3 — Confirm startup log (optional, requires running monolith)**

1. Ensure `monolith-db` is running (`docker compose up monolith-db -d`)
2. Start the monolith with the `local` profile (provides a dev signing key):

Linux/Mac:
```bash
cd monolith
SPRING_PROFILES_ACTIVE=local mvn spring-boot:run
```
Windows (PowerShell):
```powershell
cd monolith
$env:SPRING_PROFILES_ACTIVE="local"; mvn spring-boot:run
```

3. Watch startup logs for:

`JwtTokenService initialised: 1 verification key(s), expiry 15 min`

Confirm the log shows key **count** and expiry only — no signing key material or token strings.

**Step 4 — Decode a token manually (optional)**

After Step 3, or in a scratch unit test using `JwtTokenService` directly:

1. Issue a token for a test `User` with known enum values
2. Paste the JWT into [jwt.io](https://jwt.io) (local dev only — never paste production tokens)
3. Confirm payload contains `sub`, `iat`, `exp`, `kyc_status`, `subscription_tier`, `account_status`
4. Confirm `exp - iat` ≈ 900 seconds (15 minutes)

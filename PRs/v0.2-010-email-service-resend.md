Pull request: Email Service — Resend Integration
Requesting closure of issue: #37

Note:
Introduces `EmailSender` as the sole email delivery mechanism for Phase 1. Supports two providers via configuration swap (no code change): **SMTP** (Mailpit locally, port 1025) and **Resend HTTP API** (production/staging). Three transactional templates ship at v0.2: email verification, password reset, and refresh-token replay security alert (template ready; fully wired to the notification worker in v0.5). Failed sends retry with exponential backoff (3 attempts). Recipient addresses, subjects, and bodies must never appear in logs at INFO or above — enforced by code comments and negative tests. No signup, forgot-password, or replay-consumer wiring in this PR — those call `EmailSender` in v0.2-011, v0.2-016, and v0.5.

**Backend**

* Added `monolith/src/main/java/com/stash/platform/notification/service/EmailSender.java`:
  * Spring `@Service` — single dispatch point for all outbound emails
  * **`send(EmailMessage)`** — routes to SMTP or Resend based on `stash.email.provider`
  * **`sendEmailVerification(recipientEmail, displayName, verificationUrl)`** — verification template
  * **`sendPasswordReset(recipientEmail, displayName, resetUrl)`** — password reset template
  * **`sendReplaySecurityAlert(recipientEmail, displayName)`** — replay security alert (preview; consumer wiring in v0.5)
  * Provider routing:
    * `smtp` — Spring `JavaMailSender` → Mailpit locally (`localhost:1025` by default)
    * `resend` — `WebClient` POST to `https://api.resend.com/emails` with `Authorization: Bearer {RESEND_API_KEY}`
  * Retry: `@Retryable` — 3 attempts, exponential backoff (1s → 2s → 4s); `@Recover` logs failure without PII and throws `EmailSendException`
  * Uses existing `correlationAwareWebClient` bean for Resend calls (correlation ID forwarded)

* Added `monolith/src/main/java/com/stash/platform/notification/service/EmailMessage.java`:
  * Record: `to`, `subject`, `htmlBody`, `textBody`

* Added `monolith/src/main/java/com/stash/platform/notification/service/EmailTemplates.java`:
  * Inline HTML templates (minimal, non-branded for v0.2)
  * `verification(displayName, verificationUrl)` — 24-hour expiry note
  * `passwordReset(displayName, resetUrl)` — 1-hour expiry note
  * `replayAlert(displayName)` — security alert copy
  * `sanitise()` — HTML-escapes display names to prevent injection

* Added `monolith/src/main/java/com/stash/platform/notification/service/EmailSendException.java`:
  * Runtime exception thrown after all retry attempts fail

* Configuration:
  * `application.yml`:
    * `spring.mail.host` / `port` — `${SMTP_HOST:localhost}` / `${SMTP_PORT:1025}` (Mailpit default)
    * `stash.email.provider` — `${STASH_EMAIL_PROVIDER:smtp}`
    * `stash.email.from-address` — `${STASH_EMAIL_FROM:noreply@stash.local}`
    * `stash.email.from-name` — `${STASH_EMAIL_FROM_NAME:Stash}`
    * `stash.email.resend-api-key` — `${RESEND_API_KEY:}`
    * `stash.email.base-url` — `${STASH_BASE_URL:http://localhost:8080}` (for URL construction in callers)
  * `application-local.yml` — forces `provider: smtp` and local from-address
  * `monolith/.env.example` — documents `STASH_EMAIL_PROVIDER`, `RESEND_API_KEY`, `SMTP_HOST`, `SMTP_PORT`, etc.

* `MonolithApplication.java` — added `@EnableRetry` for `@Retryable` support

* Dependencies added to `monolith/pom.xml`:
  * `spring-retry` + `spring-aspects` (exponential backoff)
  * `spring-boot-starter-mail` (Mailpit / SMTP)

**Tests**

  * **PII must not appear in logs at INFO+** (issue DoD negative test)
    * Recipient address not in INFO+ logs during `sendEmailVerification`
    * Subject and recipient not in INFO+ logs during `sendPasswordReset`

  * **`EmailTemplates`**

**How to verify**

**Step 1 — Run the unit tests**

From the repo root:

Linux/Mac:
```bash
mvn clean test -pl monolith -Dtest=EmailSenderTest
```
Windows (PowerShell):
```powershell
mvn clean test -pl monolith "-Dtest=EmailSenderTest"
```

Confirm all nested test groups pass:
* `PII must not appear in logs at INFO+` — recipient, subject, body
* `EmailTemplates` — URL embedding and HTML sanitisation

**Step 2 — Local Mailpit smoke test (issue DoD)**

Start Mailpit (not yet in `docker-compose.yml`):

Linux/Mac:
```bash
docker run -d --name mailpit -p 8025:8025 -p 1025:1025 axllent/mailpit
```
Windows (PowerShell):
```powershell
docker run -d --name mailpit -p 8025:8025 -p 1025:1025 axllent/mailpit
```

Confirm env vars (or `.env`) use SMTP provider:

```
STASH_EMAIL_PROVIDER=smtp
SMTP_HOST=localhost
SMTP_PORT=1025
STASH_EMAIL_FROM=noreply@stash.local
```

Start the monolith with `local` profile, then trigger a send. Until v0.2-011 signup ships, use a scratch call (e.g. temporary `@SpringBootTest` or REPL) or wait for signup and run:

```java
emailSender.sendEmailVerification("you@example.com", "Test User",
    "http://localhost:8080/api/v1/auth/verify-email?token=test");
```

Open Mailpit UI at [http://localhost:8025](http://localhost:8025) and confirm the verification email arrived with correct subject and HTML body.

   ```
   RESEND_API_KEY=re_xxxxxxxx

   ```

**Step 4 — Confirm retry behaviour (optional)**

With Resend provider and an invalid API key (or Mailpit stopped), trigger a send and watch logs. Confirm:
* Up to 3 attempts with increasing delay
* Final `Email send failed after all retry attempts` at ERROR — no recipient or subject in the message
* `EmailSendException` propagated to caller

**Step 5 — Confirm startup log**

Start the monolith with `local` profile and confirm:

`EmailSender initialised: provider=smtp`

No API key, from-address, or recipient material in startup logs.

Pull request: POST/DELETE /api/v1/users/me/deletion-request
Requesting closure of issue: v0.2-019

Note:
Implements account deletion request submission and cancellation per System Design §13.13 and Schema doc §1.4. Blockers are informational-only at v0.2 — `blockers_at_submission` is an empty JSON array until susu, vault, and split modules plug in via `DeletionBlockerSnapshotProvider.BlockerCheck`. Actual account deletion execution ships in v0.5 via the cleanup job indexed by `deletion_requests_cleanup_job_idx` (v0.2-006).

**Backend**

* Added `monolith/.../domain/DeletionRequest.java`:
  * JPA entity for `user_module.deletion_requests`
  * JSONB `blockers_at_submission` mapped via hypersistence-utils `JsonType`
  * 30-day cool-off: `scheduledCompletionAt = submittedAt + 30 days`

* Added `monolith/.../repository/DeletionRequestRepository.java`:
  * `findPendingByUserId(userId)` — locates active PENDING request

* Added `monolith/.../service/DeletionBlockerSnapshotProvider.java`:
  * Extensible `BlockerCheck` interface for future susu/vault/split modules
  * At v0.2, Spring injects an empty `List<BlockerCheck>` → empty snapshot array

* Added `monolith/.../service/DeletionRequestService.java`:
  * **`submit(userId)`** — creates PENDING request; `409 USER_DELETION_REQUEST_ALREADY_PENDING` if one exists
  * **`cancel(userId)`** — sets `CANCELLED` + `cancelled_at`; `404 NOT_FOUND` if no PENDING request

* Added `monolith/.../api/dto/DeletionRequestResponse.java`

* Added `monolith/.../api/UserController.java`:
  * `POST /api/v1/users/me/deletion-request` → `201`
  * `DELETE /api/v1/users/me/deletion-request` → `204`

* Checked out from **v0.2-015** (prerequisite only):
  * `AuthenticatedUser.java` — JWT-backed `Authentication` principal for controller

* Updated `shared/api-errors/.../ErrorCode.java`:
  * `USER_DELETION_REQUEST_ALREADY_PENDING`

* Updated `monolith/pom.xml`:
  * `hypersistence-utils-hibernate-63` 3.7.3 for JSONB mapping

* Dependencies:
  * v0.2-006 — `user_module.deletion_requests` Flyway migration (V5)
  * v0.2-011 — `SignupService` (test helper)
  * v0.2-015 — `AuthenticatedUser` + Spring Security JWT wiring (**merge 015 before 019** for live endpoint auth)

**Tests**

* `DeletionRequestServiceTest` — `@SpringBootTest` + Testcontainers Postgres; `EmailSender` mocked:
  * Happy submit: PENDING row, 30-day schedule, empty blocker array
  * Duplicate submit → `409 USER_DELETION_REQUEST_ALREADY_PENDING`

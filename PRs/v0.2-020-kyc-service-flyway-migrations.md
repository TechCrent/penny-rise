Pull request: Flyway Migrations — KYC Service tables (submissions, documents, provider decisions, review queue, deletion jobs)
Requesting closure of issue: #47

Note:
Adds all five KYC Service tables to `kyc-db` per issue v0.2-020. The canonical Schema doc §8 defines three tables (`kyc_submissions`, `kyc_documents`, `kyc_deletion_attempts`); this PR maps those plus two explicit additions from the issue:

* `kyc.submissions` — Schema doc §8.1 (`kyc_submissions`)
* `kyc.submission_documents` — Schema doc §8.2 (`kyc_documents`)
* `kyc.document_deletion_jobs` — Schema doc §8.3 (`kyc_deletion_attempts`)
* `kyc.provider_decisions` — **not in Schema doc §8**; append-only provider response log (issue-requested addition; pending doc sign-off)
* `kyc.manual_review_queue` — **not in Schema doc §8**; claim/lock queue per Wireframes doc A5 (issue-requested addition; pending doc sign-off)

`user_id`, `reviewer_admin_id`, and `claimed_by_admin_id` are logical references only — no cross-database FKs (Module Boundaries doc Rule 4). All intra-`kyc` FKs use `ON DELETE CASCADE`. Migrations are forward-only.

**Backend**

* Removed stub `.gitkeep` files from `db/migration/submission/` and `db/migration/document/` (v0.1-007 stubs)

* Added `kyc-service/src/main/resources/db/migration/submission/V1__create_kyc_submissions.sql`:
  * Creates `kyc` schema and `kyc.submissions`
  * Columns: `id`, `user_id` (logical ref), `ghana_card_number`, `full_name_on_card`, `date_of_birth`, `phone_number`, `status`, `review_path`, `provider_decision`, `provider_reference`, `reviewer_admin_id` (logical ref), `decision`, `decision_reason`, `submitted_at`, `decided_at`, `correlation_id`
  * CHECK constraints on `status` (`SUBMITTED`, `REVIEWING`, `APPROVED`, `REJECTED`, `RESUBMISSION_REQUIRED`), `review_path` (`AUTO`, `MANUAL`), `decision` (`APPROVED`, `REJECTED`)
  * Indexes: `submissions_user_id_idx`, partial `submissions_status_submitted_at_idx` for queue ordering

* Added `kyc-service/src/main/resources/db/migration/document/V1.1__create_kyc_submission_documents.sql`:
  * **Version 1.1** (not 1) — guarantees it runs after `submission/V1` which it FK-depends on
  * Creates `kyc.submission_documents` with deferred-deletion state machine (`RETAINED` → `PENDING_DELETION` → `DELETED` / `DELETE_FAILED`)
  * FK to `kyc.submissions` with `ON DELETE CASCADE`
  * UNIQUE `(submission_id, document_type)` — one document per type per submission
  * Partial index `submission_documents_deletion_worker_idx` for v0.2-027 deletion worker

* Added `kyc-service/src/main/resources/db/migration/submission/V2__create_kyc_provider_decisions.sql`:
  * Creates `kyc.provider_decisions` — append-only provider response log
  * **Flagged in migration comments:** NOT in canonical Schema doc §8; pending doc sign-off
  * `raw_response JSONB` for full provider payload retention
  * CHECK on `decision` (`PASS`, `FLAGGED`, `FAIL`, `ERROR`, `TIMEOUT`)

* Added `kyc-service/src/main/resources/db/migration/submission/V3__create_kyc_manual_review_queue.sql`:
  * Creates `kyc.manual_review_queue` — claim/lock semantics per Wireframes doc A5
  * **Flagged in migration comments:** NOT in canonical Schema doc §8; pending doc sign-off
  * `claim_expires_at` for 30-minute stale-lock expiry
  * UNIQUE `submission_id` — one active queue row per submission

* Added `kyc-service/src/main/resources/db/migration/document/V4__create_kyc_document_deletion_jobs.sql`:
  * **Version 4** (renamed from V1.2) — Flyway sorts `1.2` before `2`; V4 ensures order `V1 → V1.1 → V2 → V3 → V4`
  * Creates `kyc.document_deletion_jobs` per Schema doc §8.3
  * One row per deletion attempt (append-only audit trail)
  * FK to `kyc.submission_documents` with `ON DELETE CASCADE`

* Final Flyway apply order:
  1. `submission/V1` — `kyc.submissions`
  2. `document/V1.1` — `kyc.submission_documents`
  3. `submission/V2` — `kyc.provider_decisions`
  4. `submission/V3` — `kyc.manual_review_queue`
  5. `document/V4` — `kyc.document_deletion_jobs`

* No JPA entities, repositories, or KYC service code in this PR — those ship in later v0.2 issues

  * Valid provider decision insert succeeds
  * Duplicate `manual_review_queue.submission_id` fails UNIQUE constraint
  * `document_deletion_jobs` with unknown `document_id` fails FK
  * Deleting a submission cascades to documents, provider decisions, queue entries, and deletion jobs

**Important — `docker compose up` does NOT start the KYC Service**

`docker compose up -d` starts Postgres and RabbitMQ only. The KYC Service must be started manually via `mvn spring-boot:run` to trigger Flyway. The verification steps below will not produce the migrated schema if the service is not started.

**Prerequisites:** JDK **21** (project target) and **Docker** running (Testcontainers needs it for Step 9). Ensure `kyc-db` is available (port 5434 by default).

**How to verify**

**Step 1 — Start kyc-db on a clean state**

If `kyc-db` is already running from previous work, recreate it so Flyway runs against an empty database.

From the repo root:

Linux/Mac:
```bash
docker compose down -v
docker compose up kyc-db -d
```
Windows (PowerShell):
```powershell
docker compose down -v
docker compose up kyc-db -d
```

Wait for `stash-kyc-db` to reach a healthy state.

**Step 2 — Start the KYC Service and trigger Flyway**

Open a new terminal.

From the repo root:

Linux/Mac:
```bash
cd kyc-service
mvn spring-boot:run
```
Windows (PowerShell):
```powershell
cd kyc-service
mvn spring-boot:run
```

Watch the logs for Flyway output. Confirm all five migrations apply in order:

```
Migrating schema "kyc" to version "1 - create kyc submissions"
Migrating schema "kyc" to version "1.1 - create kyc submission documents"
Migrating schema "kyc" to version "2 - create kyc provider decisions"
Migrating schema "kyc" to version "3 - create kyc manual review queue"
Migrating schema "kyc" to version "4 - create kyc document deletion jobs"
Successfully applied 5 migrations
```

**Step 3 — Confirm the tables exist**

Open a new terminal.

Connect to `kyc-db`:

Linux/Mac:
```bash
docker exec -it stash-kyc-db psql -U stash_kyc -d kyc_db
```
Windows (PowerShell):
```powershell
docker exec -it stash-kyc-db psql -U stash_kyc -d kyc_db
```

Then run:
```sql
\dn kyc
\dt kyc.*
```

Confirm all five tables are listed.

**Step 4 — Confirm submissions schema**

While still connected via `psql`:
```sql
\d kyc.submissions
```

Confirm all columns from Schema doc §8.1 with correct types, CHECK constraints on `status`, `review_path`, and `decision`, and no FK on `user_id`.

**Step 5 — Confirm all FKs stay within kyc schema**

While still connected via `psql`:
```sql
SELECT
    tc.table_name, tc.constraint_name, ccu.table_schema AS foreign_schema
FROM information_schema.table_constraints tc
JOIN information_schema.constraint_column_usage ccu
    ON tc.constraint_name = ccu.constraint_name
WHERE tc.table_schema = 'kyc'
  AND tc.constraint_type = 'FOREIGN KEY';
```

Confirm every row shows `foreign_schema = kyc`.

**Step 6 — Confirm Flyway history**

While still connected via `psql`:
```sql
SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;
```

Confirm versions `1`, `1.1`, `2`, `3`, `4` are all present with `success = t`.

Exit psql:
```sql
\q
```

**Step 7 — Run the tests**

From the repo root:

Linux/Mac:
```bash
mvn clean test -pl kyc-service -Dtest=KycMigrationsTest,KycConstraintsTest
```
Windows (PowerShell):
```powershell
mvn clean test -pl kyc-service "-Dtest=KycMigrationsTest,KycConstraintsTest"
```

Confirm both `KycMigrationsTest` and `KycConstraintsTest` pass. Use `clean` to avoid stale `target/` artifacts from other branches. Requires Docker running for Testcontainers.
